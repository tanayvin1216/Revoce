# Research Brief: Prior Art and Fixes for Distilled AAC Vocabulary-Ranking Quality (Distillation, Diversity, Rare-Answer Representability)

## Question
Given the measured VoiceLink Phase-4 failure modes (raw-topk inference with no redundancy penalty, an un-deduped vocabulary where 7 hedge paraphrases occupy 19% of slots, and a `min_freq=3` floor that makes rare concrete answers structurally unrepresentable), what does the AAC and ML literature say about the right fixes for context-aware vocabulary prediction, semantic label dedup, diversity-aware slate selection, slate-policy distillation, and honest evaluation — and how should VoiceLink prioritize them?

## Key Findings

### 1. Prior art on context-aware AAC vocabulary prediction
- **KWickChat** (Shen et al., IUI 2022) generates full context-aware AAC utterances from a few keywords using GPT-2 conditioned on dialogue history and persona; reports keystroke savings (~71% at WER 0.65) as its headline metric — the field's evaluation focus is *communication rate*, not diversity of the candidate set. (confidence: HIGH) — [ACM DL](https://dl.acm.org/doi/10.1145/3490099.3511145), [ouci mirror](https://ouci.dntb.gov.ua/en/works/4Lg08yq7/)
- **PrAACT** (Predictive AAC with Transformers, ScienceDirect 2024) and the Brazilian-Portuguese predictive-authoring work extend transformer word/phrase prediction into AAC but likewise optimize keystroke/selection savings, not redundancy in the *offered set*. (confidence: MEDIUM) — [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0957417423029196), [arXiv 2308.09497](https://arxiv.org/pdf/2308.09497)
- **"Adapting LLMs for Character-based AAC"** (arXiv 2501.10582): AAC users are "enthusiastic but cautious" about LLM assistance, citing autonomy concerns — relevant to why VoiceLink pins deterministic core words rather than trusting the model fully. (confidence: MEDIUM) — [arXiv](https://arxiv.org/pdf/2501.10582)
- **Visual Scene Displays (VSD)** literature frames AAC vocabulary as "situated language use" and describes "just-in-time" vocabulary programming tied to activity context — conceptually validates VoiceLink's premise (scene+transcript-driven boards) but gives no quantitative diversity metric. (confidence: MEDIUM) — [PMC6436972](https://pmc.ncbi.nlm.nih.gov/articles/PMC6436972/), [ASHA Perspectives](https://pubs.asha.org/doi/10.1044/2022_PERSP-22-00162)
- **No commercial system found (TD Snap, Proloquo2Go, CoughDrop) publishes a diversity-of-candidate-set metric.** None appear to run MMR/DPP-style redundancy control at the board level. This is a genuine gap VoiceLink's `_select_dynamic` MMR (rank_vocabulary.py:503-550) already fills better than documented commercial state of the art. (confidence: MEDIUM — absence of evidence) — [Forbes AAC](https://www.forbesaac.com/choose-your-app-proslate-10), [AssistiveWare blog](https://www.assistiveware.com/blog/proloquo-or-proloquo2go)
- **Takeaway:** the field's standard metric is task-completion/keystroke-savings, not "was a non-redundant answer set offered." VoiceLink's `coverage_of_intent` + `distinct_functions@k` + `near_dup_rate` combination is more rigorous than published AAC baselines — RC-1/RC-2/RC-3 are implementation bugs, not an unsolved-in-the-field problem.

### 2. Semantic dedup of the label/vocab space
- Standard practice (NVIDIA NeMo SemDeDup): embed items, cluster, compute pairwise cosine within cluster, keep one representative per near-duplicate group; thresholds are dataset-specific and swept, not fixed. (confidence: HIGH) — [NVIDIA NeMo docs](https://docs.nvidia.com/nemo-framework/user-guide/24.09/datacuration/semdedup.html)
- Multi-label literature clusters *label embeddings* into fewer super-labels before training — directly analogous to collapsing the 7 hedge phrases into one canonical "I don't know" label before `build_vocab` assigns frequency ranks. (confidence: MEDIUM — pattern-matched, no single canonical paper)
- SemHash and similar tools operationalize "cluster, keep centroid representative, drop rest" — same shape as the INVESTIGATION's proposed fix. (confidence: MEDIUM) — [Medium/SemHash](https://medium.com/@sreeprad99/how-semhash-simplifies-semantic-deduplication-for-llm-data-a0b1a53e84fe)

### 3. Diversity-aware inference: MMR vs DPP vs submodular
- **MMR** (Carbonell & Goldstein 1998): greedy, `argmax λ·relevance(d) − (1−λ)·max_sim(d, selected)`; simple, no retraining, "has powered production systems for decades." Exactly what `rank_vocabulary.py`'s `_select_dynamic`/`mmr_select` already implements for the teacher path. (confidence: HIGH) — [ResearchGate MMR paper](https://www.researchgate.net/publication/2269571_The_Use_of_MMR_Diversity-Based_Reranking_for_Reordering_Documents_and_Producing_Summaries), [Medium MMR walkthrough](https://medium.com/data-science-collective/diversity-in-recommendations-maximal-marginal-relevance-mmr-0e7840c9399e)
- **DPP** is theoretically stronger (scores whole subsets via determinant; catches redundancy MMR's greedy myopia misses); greedy MAP approximation is tractable at small k. Small win over MMR at k_dyn=6, nontrivial engineering cost. (confidence: HIGH theory, MEDIUM worth-it) — [Kulesza & Ghahramani DPP monograph](http://www.alexkulesza.com/pubs/dpps_fnt12.pdf), [Medium DPP walkthrough](https://medium.com/data-science-collective/diversity-in-recommendations-determinantal-point-processes-dpp-2427bf1b6324)
- **Recommendation**: MMR is the simplest and most defensible for a 10-slot board — it's what the teacher seam already runs (`ANSWER_LAM=0.35` for answer-mode), so porting the *same* selection code into the student path (not a new algorithm) is the cheapest and most consistent fix. DPP is a plausible v2 upgrade only if MMR still leaves residual clustering; the current bottleneck is that the student runs *no* selection at all (raw `topk`).

### 4. Distillation of a ranker/slate policy: listwise vs pointwise, and mode collapse
- Ranking-distillation literature is consistent: **pointwise distillation loses relative-order information and is the weaker choice when the teacher's real behavior is a ranking/set decision**; listwise losses preserve order but can hurt calibration. VoiceLink's BCE-over-vocab is pointwise — exactly the class flagged as insufficient for capturing a teacher's *selection* behavior. (confidence: HIGH) — [arXiv 2408.14678](https://arxiv.org/html/2408.14678), [arXiv 2109.15285](https://arxiv.org/pdf/2109.15285), [PLD paper](https://arxiv.org/pdf/2506.12542)
- Long-tail multi-label literature directly names RC-2's mechanism: under plain BCE, "head labels dominate the gradient," and correlated frequent positive labels (the 7 hedges) get systematically over-weighted while tail labels are under-trained. **Distribution-Balanced Loss** (rebalanced weighting for label co-occurrence + negative-tolerant regularization) is a documented, citable fix class for this exact failure. (confidence: HIGH) — [arXiv 2007.09654](https://arxiv.org/abs/2007.09654), [KDnuggets summary](https://www.kdnuggets.com/2023/03/multilabel-nlp-analysis-class-imbalance-loss-function-approaches.html)
- **Set vs ranking objective**: the teacher performs answer-quota-reservation + MMR at generation time (a *selection* policy), so distilling into a pointwise multi-label classifier throws away exactly the selection logic that made the teacher good. Defensible paths: (a) keep pointwise/BCE for *relevance* scoring only and re-add MMR/DPP selection at inference (cheap — matches remediation item 2), or (b) listwise/set-based distillation (set-prediction loss / Hungarian matching) — higher fidelity, much bigger rewrite. (confidence: MEDIUM — synthesized)

### 5. Open vocabulary / rare answers (RC-3)
- **Two-stage candidate-generation + ranking** is the standard industrial pattern (YouTube/Pinterest-style): cheap retrieval proposes a wide pool (can include rare/unseen items), a separate ranker scores/selects — maps directly onto the teacher architecture (`generate_pool` then `select_board`), which is why the teacher doesn't suffer RC-3: it doesn't rely on a fixed frequency-filtered vocab at generation time, only at student-distillation time. (confidence: HIGH) — [Two-stage rec-sys theory](https://arxiv.org/pdf/2403.00802), [Google Cloud two-tower retrieval](https://docs.cloud.google.com/architecture/implement-two-tower-retrieval-large-scale-candidate-generation)
- **Copy/pointer mechanisms** (pointer-generator networks) let a model emit phrases copied from the input rather than only from a fixed output vocabulary — the canonical fix for the "sugar"/"window seat"/"over there" problem: the answer is often lexically present in the transcript or scene, and a copy mechanism sidesteps the frequency floor entirely. (confidence: HIGH for mechanism; MEDIUM for applicability to a small-MLP student — would require a hybrid generate-or-copy head, or keeping the student purely as a *ranker* over per-context candidates) — [GeeksforGeeks Pointer-Generator overview](https://www.geeksforgeeks.org/python/pointer-generator-networks-in-nlp/), [arXiv 1808.06885](https://arxiv.org/pdf/1808.06885)
- **Simplest defensible fix given VoiceLink's architecture**: don't make the student generative. Generate per-context candidates from transcript/scene at inference (cheap noun-phrase / entity extraction, or reuse `topics_from_context`) and union them with the fixed vocab before scoring — candidate-generation-plus-ranking applied at the cheapest possible layer, consistent with "simple version first".

### 6. Evaluation: measuring slate quality honestly, and how it gets gamed
- Coverage@K / Entropy@K diversity metrics are known to be gameable when computed over a set including pinned/forced items — precisely the finding that `coverage_of_intent@7 = 0.958` is inflated by 4 always-pinned core words (11/71 scenarios pass solely via core-word lexical matches). (confidence: HIGH — measured in-repo + consistent with Goodhart/reward-hacking literature) — [reward-hacking summary](https://arxiv.org/html/2507.05619v1), `INVESTIGATION_useless_boards.md:104-131`
- Standard mitigation across the reward-hacking literature: **multi-objective evaluation with metrics that are hard to game simultaneously** — i.e., score coverage on `sb_dynamic` (post-core-removal) and add a same-communicative-function-pair fraction rather than relying on `near_dup_rate`'s single cosine threshold (which dilutes to 0.02 vs the real 0.169). (confidence: HIGH)
- No literature validates the 0.85 cosine `near_dup_rate` threshold in general — it's a project-specific parameter; the in-repo measurement (hedge pairs at cosine 0.78–0.94 straddling 0.85) is the most authoritative evidence available. (confidence: LOW on threshold correctness — an unknown, not a finding)

## Recommendations (ranked by leverage vs. effort)

1. **Port the teacher's MMR selection into the student inference path, replacing raw `torch.topk`** (student.py:39-46). Standard, cheap, no-retrain fix for redundancy; highest leverage per the INVESTIGATION's remediation item 2. Effort: low (reuse `mmr_select`/`build_query_vector`).
2. **Canonicalize the vocab via semantic dedup before frequency ranking** (`data.py:build_vocab`), collapsing the 7 hedge paraphrases into one label at cosine ≥0.80 (SemDeDup-style), then retrain. Attacks RC-2 at the training-target level — MMR alone cannot fully fix a training signal where 7 correlated frequent labels co-inflate each other's logits. Effort: medium (pipeline change + retrain).
3. **Fix the evaluation gates to score `sb_dynamic` (core-removed) and add a same-function-pair diversity metric** — multi-metric, hard-to-game-simultaneously evaluation. Ship alongside #1 so regressions are visible immediately. Effort: low.
4. **Add a lightweight candidate-generation step for open-vocabulary rare answers** (extract noun phrases/entities from transcript+scene at inference, union with fixed vocab before scoring) rather than a copy-mechanism/generative rewrite. Effort: medium.
5. **Consider Distribution-Balanced Loss as a training-time complement to #2**, if semantic dedup alone doesn't rebalance gradients toward rare concrete answers. Lower priority. Effort: medium-high.
6. **DPP-based selection is not currently justified** — revisit only if MMR-in-student still shows residual redundancy after retraining.

## Risks
- **Listwise/set-objective distillation is a much larger rewrite** — don't attempt under "simple version first" without first validating that pointwise-BCE-plus-MMR is insufficient.
- **Semantic dedup threshold (0.80) is project-chosen, not literature-validated** — sweep it against held-out data; NeMo's docs explicitly warn thresholds are dataset-specific.
- **Fixing the evaluation gates will likely make currently-"passing" boards fail** — expect the PASS/FAIL story to change; plan the retrain/re-eval cycle before communicating results externally.

## Unknowns
- No literature directly validates the 0.85 `near_dup_rate` threshold or provides a canonical "same-communicative-function" clustering method for AAC phrases — `taxonomy.classify_functions` is locally engineered; validate against AAC communicative-functions literature if it becomes a public claim.
- No published academic or commercial AAC system found that benchmarks candidate-set diversity/redundancy the way Phase-3/4 metrics do — a genuine novelty angle, but absence of contrary evidence is not proof of true novelty.
- KWickChat full paper paywalled — could not confirm whether it addresses near-duplicate suggestion filtering.
